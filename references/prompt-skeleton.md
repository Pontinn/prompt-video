# Prompt skeleton

Every prompt generated by `/prompt-video` follows this skeleton. Blocks marked MANDATORY always appear. Blocks marked CONDITIONAL appear when the request needs them. Depth scales with the complexity of the request: a simple request gets short blocks, a complex request gets blocks as deep as `examples/example-1-talking-head-reel.txt`.

## Order of blocks

```
OPENING PARAGRAPH                       MANDATORY
MEDIA RESTRICTIONS                      MANDATORY
AUDIO RESTRICTIONS                      MANDATORY
ENVIRONMENT                             CONDITIONAL (any dependency involved)
AUTONOMY                                CONDITIONAL (inputs or selection decisions)
INPUTS                                  CONDITIONAL (user provided files)
DELIVERABLES                            MANDATORY
1..N NUMBERED RULE BLOCKS               MANDATORY core + CONDITIONAL extras
PLAN BEFORE BUILDING                    MANDATORY
FINAL VERIFICATION                      MANDATORY
REPORT / DELIVERY                       MANDATORY
```

## Mandatory blocks

### OPENING PARAGRAPH
One or two sentences. What to create, for which destination, duration, resolution written as `1080 × 1920 pixels`, frame rate written as `60 frames per second`. Name the stack explicitly and say the video is built and rendered with the HyperFrames skill (`/hyperframes`). Example shape:

> Create a 20-second vertical 9:16 video for Instagram Reels about X. Build everything by code with the HyperFrames skill (/hyperframes), using HTML, CSS, SVG, canvas and GSAP for the compositions, and render to MP4 at 1080 × 1920 pixels and 60 frames per second.

### MEDIA RESTRICTIONS
- Everything on screen is created by code (HTML, CSS, SVG, canvas, GSAP, Three.js).
- No stock images or videos, no AI-generated media, no video editing applications.
- Exception: files listed in INPUTS.

### AUDIO RESTRICTIONS
- Music and sound effects synthesized by code (Web Audio API rendered offline with OfflineAudioContext, or NumPy and SciPy), exported to WAV and embedded in the MP4.
- No external audio files, no samples.
- Exception: a voice file listed in INPUTS.

### DELIVERABLES
- Output folder name (new folder, for example `edit`, `trailer`, `clawd`).
- Final file: `final.mp4`, resolution, fps, H.264 high quality, AAC stereo 48 kHz.
- Auxiliary files: stems (`stems/voice.wav`, `stems/music.wav`, `stems/sfx.wav`) when relevant, project files needed to reproduce the render, verification contact sheets.
- A short report (contents listed in REPORT).

### Core numbered rule blocks (always present, named freely)
1. VISUAL IDENTITY: palette in hex, typography with family, size in pixels and weight, minimum text size, corner radii, shadow recipe when cards are involved, overall tone in one sentence.
2. MOTION: every movement uses named GSAP easing (sine.inOut, power2.inOut, power3.in, power3.out); durations in seconds; no constant-velocity motion; no fully static scene (keep subtle motion during reading pauses); depth through scale, blur and parallax; transitions born from the scene elements, no generic dissolves.
3. RHYTHM AND LEGIBILITY: one idea at a time; nothing disappears before it can be read; minimum on-screen time for text; one subject per scene plus at most one supporting element.
4. SOUND: what to synthesize (music style, tempo in BPM, SFX list tied to visual events); sync with beats or events; levels relative to voice or to each other in dB; music below voice; clean mix; loudness targets (LUFS integrated, true peak dBTP) when the request is for publication.

### PLAN BEFORE BUILDING
Before any code, write a technical script, storyboard or segment table covering 0 to END: start, end, what is on screen, what the viewer must understand, what the audio does. In audio-led modes, paste the draft segment table produced by the analysis so the executing session starts from it.

### FINAL VERIFICATION
- Inspect real rendered frames, not the preview.
- Generate a contact sheet of the whole video.
- Image checklist: duration, resolution, fps, legibility, safe areas, cut boundaries (both sides of each cut), no frozen frame, no blank frame, no mask errors, cover clean on frame 0 when there is one.
- Audio checklist: every SFX matches its visual event, loudness targets within 0.5 LU, true peak within limit, no gap over 150 ms at joins when speech is involved, music under voice.
- Fix every failure and render again. Deliver only after verification passes.

### REPORT / DELIVERY
- Final MP4 plus everything needed to reproduce the render.
- Report: decisions taken, substitutions, verified facts and sources when facts are mentioned, SFX list with times, loudness per track, verification result, what is pending if the environment blocked something.

## Stacks by nature of the request

- Editing real footage: FFmpeg, Python, Node, HyperFrames.
- 2D motion graphics: HTML, CSS, SVG, canvas, GSAP, HyperFrames.
- 3D: Three.js, HyperFrames.
- Audio: Web Audio API with OfflineAudioContext, or NumPy and SciPy.
- Transcription: HyperFrames transcription, Whisper or equivalent local tool.
- Background removal and interface capture: HyperFrames or equivalent.

## Defaults when the user does not specify

- Reels, TikTok, Shorts: 1080 × 1920 pixels, 60 frames per second, H.264 high quality, AAC stereo 48 kHz.
- Landscape trailer or explainer: 1920 × 1080 pixels (or 2560 × 1440 for cinematic), 60 frames per second.
- 3D animation: 1920 × 1080 pixels, 30 frames per second.
- Palette: cream #F0EEE6, ink black #1F1E1D, clay orange #D97757, confirmation green #34C759, stamp red #FF3B30, highlight band #FBEEE8.
- Typography: Poppins for UI and captions (titles 96 px weight 700, subtitles 52 px weight 700, body 30 px weight 400, nothing under 30 px); an elegant serif such as Instrument Serif for cinematic titles and caption highlights.
- Shadows for elevated objects: three layers, 60 px offset 120 px blur rgba(24,24,32,0.16); 24 px offset 48 px blur rgba(24,24,32,0.10); 4 px offset 10 px blur rgba(24,24,32,0.06).
- Corner radii: media cards 3% of width, documents 40 px, blocks 72 px, phones 84 px.
- Music: 100 to 120 BPM, instrumental, minimal, no lead melody competing with speech, first beat on frame 1, 800 ms fade out, single level with no ducking.
- Loudness for publication: voice -14 LUFS, music about -24 LUFS, master -14 LUFS and -1 dBTP.
- Output folder: `edit` for footage editing, otherwise a short name derived from the subject.

## Style rules for the prompt text

- English, imperative, addressed to Claude: "Create", "Use", "Do not use", "Keep", "Never".
- One rule per line. Short sentences. No long paragraphs inside rule blocks.
- Section titles in CAPITALS without markdown syntax. Numbered sections "1. TITLE" or "N. Short sentence".
- Sublists numbered "1. 2. 3." or lettered "A. B. C.". No markdown bullets.
- Concrete numbers everywhere. Never "a bit of blur", always "up to 14 pixels of blur".
- Units spelled out where natural ("frames per second", "pixels", "seconds"); technical abbreviations where standard (ms, dB, LUFS, dBTP, BPM, Hz).
- Resolution as "1920 × 1080 pixels" with the × symbol.
- Colors in hex or rgba().
- Easing named in GSAP form.
- Explicit prohibitions: "Never", "Do not use", "Avoid", "must be treated as an error".
- HyperFrames named by name in the opening and in the render section.
- Always close with verification and delivery. Never end on a loose rule.
- No em dash anywhere.
