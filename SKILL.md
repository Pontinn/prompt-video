# Prompt Video

Turns a request (and optionally raw video or audio files) into a complete prompt that Claude Code executes to produce a video with the HyperFrames skill. This skill never produces the video. It analyzes inputs, talks to the user, writes the prompt and saves it.

## Language rules

- Talk to the user in Brazilian Portuguese: questions, suggestions, progress updates, confirmations.
- The generated prompt is written in English, unless the user explicitly asks for Portuguese.
- File names, folder names and technical terms stay as they are (final.mp4, stems/voice.wav, HyperFrames, GSAP, sine.inOut).
- Never use an em dash in anything you write (chat, prompt, files). Use a period, comma, colon, parentheses or a plain hyphen.

## Hard rules

1. Every generated prompt explicitly says the video is built and rendered with the HyperFrames skill (`/hyperframes`). State it in the opening paragraph and again in the render section.
2. Never generate a prompt about a media file you did not inspect. Video analysis and audio transcription are mandatory before writing (see `references/media-analysis.md`).
3. Never edit, convert in place, move, rename or delete the user's files. Analysis only reads. Temporary analysis output goes to a scratch folder, never into `brutos/` or `prompts/`.
4. Never install anything globally. If a tool is missing, install it locally inside the project (Python venv, npm in the project folder) or pick another approach.
5. Only enter suggestion mode when the user asks for ideas. Never volunteer concepts on a vague request; ask what is missing instead.
6. Detail is proportional to the request. The mandatory blocks always appear; their depth and the number of conditional blocks scale with complexity (see `references/prompt-skeleton.md`).
7. The prompt is delivered in chat AND saved as a .txt in `prompts/`. Never overwrite an existing .txt.
8. Load `references/prompt-skeleton.md` before writing any prompt. Load `references/media-analysis.md` before analyzing any file. Read the matching file in `examples/` for the closest reference.

## Workflow

### Step 1. Scan the current directory

List top-level folders and files. Identify:
- Loose media files (mp4, mov, mkv, webm, wav, mp3, m4a, aac, flac, png, jpg).
- An existing `brutos/` folder and what it contains.
- An existing `prompts/` folder and the most recent .txt files in it (by name or modification time).
- Any existing HyperFrames project (`hyperframes.json`, `BRIEF.md`, `STORYBOARD.md`) or output folder from a previous run (`edit/`, `clawd/`).

Do not touch anything. Report the findings to the user in two or three lines of Portuguese.

### Step 2. Prepare the raw-files folder

- If `brutos/` does not exist, create it. Tell the user: coloque os arquivos crus (vídeo, áudio, imagens) dentro de `brutos/` e avise quando terminar. Also say that no files are needed if the video will be created from scratch.
- If `brutos/` already exists and has files, ask whether to use those files or whether new ones are coming.
- If `prompts/` does not exist, create it now so the final save never fails.
- If `prompts/` already has files, list the three most recent and offer to reuse or adapt one. If the user picks one, read it and treat it as the starting point for the new prompt.
- If loose media exists in the directory root, point it out and ask whether it should be considered input. Never move it yourself.

Then wait for the user. The user may also say there are no files, which is text mode.

### Step 3. Inventory the inputs

Classify what is in `brutos/`:

| Inputs found | Mode |
|---|---|
| Nothing | Text mode: the prompt describes a video built from scratch. |
| Video only | Video mode (`references/media-analysis.md` § Video). |
| Audio only | Audio mode: the narration drives everything, all visuals are generated by code. |
| Audio + video | Audio-led mode: the narration drives, the video is illustrative b-roll. |
| Video with embedded audio + separate clean audio | Talking-head mode: sync both by cross-correlation, use only the clean audio (Example 1). |
| Video the user calls a reference | Reference mode: extract style rules (rhythm, cuts, type, color, motion, sound), never use it as footage. |
| Images only | Asset mode: images are input assets to be placed in generated compositions. |

Ask the user only if the role of a file is ambiguous (for example two videos with no explanation).

### Step 4. Analyze the media (mandatory)

Follow `references/media-analysis.md`. Minimum output of the analysis, kept in your working notes:
- Per file: duration, resolution, aspect, fps, codecs, audio channels and sample rate.
- Video: orientation, content type (talking head, screen recording, product, scene, animation), scene changes, visible text, logos, interfaces, dominant colors, problems (shaky, dark, off-camera gaze, dead sections).
- Audio: word-level transcription, sentence list with timestamps, pauses longer than 250 ms, repeated takes, hook, call to action, key mentions (products, numbers, facts), quality problems.
- Audio + video together: a segment map (start, end, what is said, what the footage shows or what must be generated). This map becomes the segment table inside the prompt.

Summarize the analysis to the user in Portuguese in five to ten lines before going on. Do not paste the full transcript unless asked.

### Step 5. Gather what is missing

Compare the request against the minimum information list:
1. Nature and subject of the video (what it is, for whom, where it will be published).
2. Duration (or "driven by the narration" in audio mode).
3. Resolution, aspect ratio and fps.
4. Visual identity (palette, fonts) or "let Claude decide".
5. On-screen text: captions, cover title, call to action, none.
6. Audio: music only, music + SFX, provided voice, no narration.
7. Output folder name for the final render.

Apply the defaults from `references/prompt-skeleton.md` § Defaults for anything with a reasonable default. Ask in ONE round, using AskUserQuestion, only for the items that change the result and have no safe default. Never ask more than four questions.

### Step 6. Suggestion mode (only when asked)

Trigger: the user explicitly asks for ideas ("me dá ideias", "o que dá pra fazer", "sugere algo", "não sei o que fazer com isso").

- If there are files in `brutos/`, Step 4 must be complete before suggesting. Never suggest without having inspected the files.
- Present exactly 3 proposals as a numbered list in chat, in Portuguese. Each proposal has: concept in one sentence, format (aspect, duration, destination), short structure (opening, middle, closing), visual and sound tone, which example in `examples/` is the closest base, and, in video or audio mode, which findings from the analysis justify it.
- Say which proposal you recommend and why, in one sentence.
- Wait for the choice. The user may pick one, mix two, or ask for three more. If the user says "faz a que você acha melhor", generate the recommended one without asking again.
- Keep proposals short. Do not write the full prompt for each one.

### Step 7. Write the prompt

Load `references/prompt-skeleton.md` and the closest file in `examples/`. Build the prompt in English following the skeleton exactly:
- Opening paragraph with the deliverable, format, duration, resolution, fps and the HyperFrames skill named explicitly.
- Media and audio restrictions (everything by code, no stock, no AI-generated media, audio synthesized by code unless a voice file is provided).
- Environment block when any dependency is involved (local installs only).
- Autonomy block when there are inputs or selection decisions.
- INPUTS block listing the real paths inside `brutos/` with the facts from the analysis (duration, resolution, fps, orientation, what it contains). Never use generic placeholders.
- DELIVERABLES block with the output folder, final file specs, auxiliary files and report.
- Numbered rule blocks in capitals: visual identity, motion, rhythm and legibility, sound, plus the conditional blocks the request needs.
- PLAN BEFORE BUILDING block. In audio or audio-led mode, include the segment map from Step 4 as the draft segment table.
- FINAL VERIFICATION block (real rendered frames, contact sheet, image checklist, audio checklist, fix and re-render, deliver only after).
- REPORT block.

Style: imperative sentences, one rule per line, capitalized section titles without markdown, numbered sublists, concrete numbers everywhere (ms, px, dB, LUFS, hex, font sizes and weights, GSAP easing names), explicit prohibitions. No em dash.

### Step 8. Self-check before delivering

Go through this list and fix anything that fails:
1. HyperFrames named in the opening and in the render section.
2. Every file path in INPUTS exists in `brutos/` and the facts match the analysis.
3. All mandatory blocks present (skeleton § Mandatory blocks).
4. Every number is concrete; no "a bit", "some", "appropriate".
5. In audio modes: every segment of the narration has a visual, every cut has a reason in the speech, the final duration is the edited narration (END), the footage adapts to the narration and never the other way around.
6. Ends with verification and delivery, never with a loose rule.
7. No em dash anywhere.
8. Written in English (unless the user asked for Portuguese).

### Step 9. Deliver and save

1. Print the full prompt in chat inside a fenced text block so it can be copied in one go.
2. Save the same text to `prompts/YYYY-MM-DD-<slug>.txt`, where the slug is two to four lowercase words describing the video (for example `2026-10-15-reel-produto.txt`). If the name exists, append `-2`, `-3` and so on. Never overwrite.
3. Tell the user, in Portuguese: where the file was saved, which mode was used, which defaults were assumed, and that the prompt expects the files to stay in `brutos/`.

## Notes on HyperFrames

- HyperFrames is installed as a plugin by HeyGen. The skill is invoked as `/hyperframes` and is the mandatory entry point for any video creation in Claude Code.
- The generated prompt should tell Claude Code to use the HyperFrames skill for composition, transcription, background removal, browser or interface capture and rendering, and to fall back to FFmpeg, Python or Node only where HyperFrames does not cover a step.
- Do not invent HyperFrames CLI flags inside the prompt. Name the capability (transcribe, remove background, capture, render) and let the executing session consult the HyperFrames skill for the exact commands.
